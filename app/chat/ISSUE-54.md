# #54: 같은 질문을 수준만 바꿔 다시 묻기

[버그 이슈 #54](https://github.com/easy-explain/Codyssey-B7-1-Term-Project/issues/54)는
배포 서버에서 `easy: 도커? → easy: 더 쉽게 → advanced: 도커?` 순서로 질문할 때,
세 번째 답변이 이전 대화를 받지 못했다고 말한 사례입니다. 이슈의 배포 기준은
`61cbdab`이며, 수정 전 사례는 팀장이 관찰한 기록입니다. 수정 전 실제 AI 호출은 반복하지 않았습니다.

## 무엇을 고쳤나요?

공통 프롬프트에 다음 기준을 넣었습니다. 세 수준에 같은 기준을 적용합니다.

- 같은 주제를 다시 묻거나 수준을 바꾸면 **이번 수준으로 다시 설명**합니다.
- 이전 답변의 난이도나 이전 턴의 “더 쉽게” 요청을 이번 수준으로 계속 적용하지 않습니다.
- 질문이 짧거나 반복됐다는 이유만으로 모호하다고 판단하지 않습니다.
- 현재 질문과 전달된 문맥에서 설명 대상이 확인되면 바로 설명합니다.
- 문맥이 전달됐는데 이전 대화를 받지 못했다고 말하지 않습니다.
- 질문과 문맥을 함께 봐도 설명 대상이 불분명할 때만 확인 질문을 합니다.

전공자 지침도 이번 답변 안에서 원리·전제·한계를 설명하도록 보완했습니다.
쉬운 비유를 요약하거나 “원하면 더 설명할게요”라는 제안만으로 대신하지 않습니다.

실제로 없는 문맥을 아는 척하지 않는 지침은 유지합니다. 도커에만 적용되는 분기나
생성된 답변을 바꾸는 후처리는 넣지 않았습니다. API·DB 계약, 문맥 조회·예산,
provider와 서버 설정도 바꾸지 않았습니다.

기존 확인 질문 지침이 짧은 반복 질문에 적용됐을 가능성을 보완한 것입니다.
AI의 내부 판단 원인을 확정한 것은 아닙니다. 이슈의 네 번째 답변이 도커를 설명했다는
사실만으로 세 번째 호출의 과거 문맥 전달을 직접 증명할 수도 없습니다.

## 자동 테스트와 실제 답변을 구분합니다

`test_prompts.py`는 세 수준에 공통 지침과 이번 수준 지침이 들어가는지 확인합니다.
`test_chat_api.py`는 아래 순서에서 같은 대화를 유지하면서 매번 새 요청 키를 사용하고,
앞선 완료 질문·답변과 현재 수준이 provider에 전달되는지 확인합니다.
이 테스트는 가짜 AI를 쓰므로 실제 답변의 품질을 증명하지 않습니다.

| 순서 | 수준 | 질문 | provider에 전달된 메시지 수 |
|---|---|---|---|
| 1 | easy | 도커? | 1 |
| 2 | easy | 더 쉽게 | 3 |
| 3 | advanced | 도커? | 5 |

`quality_check.py --repeat-question`은 이 순서만 **최대 3건** 수집합니다.
로컬 채팅 서비스와 임시 DB를 거쳐 실제 코디세이 API를 호출합니다.
배포 서버의 HTTP 요청·로그인·Railway 실행을 검증하는 도구는 아닙니다.
첫 실패에서 멈추고 자동 재시도하지 않습니다. 기존 파일이 있으면 호출 전에 중단하며,
기존 EE-19·EE-23 샘플과 기본 5건 수집 계획은 보존합니다.

```bash
uv run --locked python -m app.chat.quality_check \
  --live --repeat-question --env-file /path/to/local/.env \
  --output app/chat/samples/issue-54-YYYY-MM-DD-after.json
```

| 검증 | 시각 (2026-10-10, 한국 시간) | 실제 호출 | 사람이 확인한 결과 |
|---|---|---|---|
| 1차 보완 | 18:06:44–18:07:01 | 3회 | 문맥 부정은 없지만 전공자 답변도 쉬운 설명을 반복해 **수준 변경 검토 미통과** |
| 최종 보완 | 18:07:55–18:08:24 | 3회 | 같은 대화의 앞 질문·답변을 전달받고, 반복 질문을 전공자 수준으로 바로 설명 |

호출은 총 **6회**이며, 원래의 5건 수집이나 수정 전 재현 호출은 하지 않았습니다.
두 검증 모두 요청 모델은 `claude-sonnet-4`, 관찰된 응답 모델은 `claude-sonnet-4-6`,
게이트웨이는 `copa.codyssey.kr`입니다. 문맥 5턴·12,000자, 시간 제한 30초,
출력 한도 800토큰 설정을 사용했습니다. 배포 키와의 동일성이나 잔여 한도는 확인하지 않았습니다.

최종 검증의 수동 확인 결과는 다음과 같습니다.

| 턴 | 입력/출력 토큰 | 확인한 내용 |
|---|---|---|
| 1 | 1,051 / 597 | 도커를 프로그램과 실행 환경을 담는 상자로 설명 |
| 2 | 1,658 / 257 | 도커를 이사 박스로 더 짧고 쉽게 설명하며 같은 주제 유지 |
| 3 | 1,998 / 789 | 이미지·컨테이너·레지스트리, 커널 공유·네임스페이스·cgroup, 실행 전제와 격리 한계를 설명 |

세 턴 모두 `completed`입니다. 전달 메시지는 1·3·5개이며, 앞선 실제 질문·답변이
다음 요청의 문맥과 일치합니다. 세 번째 시스템 지침은 `advanced`이고, 답변에
문맥 부정이나 불필요한 확인 질문이 없습니다. 최종 원문의 프롬프트 SHA-256
`be7aeaaf3f261aace6dfb6b877c71d8111e4588a43be3a85f2a0cab20ea28694`는 이 PR의 파일과 같습니다.

이 판정은 **#54의 반복 질문·현재 수준 반영 사례**에 한정합니다. 쉬운 답변의
“어떤 컴퓨터에서든”, “컴퓨터가 어떤 상태든 상관없어요”는 실행 전제를 생략한 과한 단순화가
남아 있습니다. 모든 답변의 사실 정확성이 통과했다고 판정하지 않습니다.
전공자 답변의 이미지·컨테이너·네임스페이스 설명은
[Docker 공식 개요](https://docs.docker.com/get-started/docker-overview/)와 대조했습니다.
현재 “핵심만” 후속 요청의 실제 출력은 이번 검증에 포함하지 않았습니다.
