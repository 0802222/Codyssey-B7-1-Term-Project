# EE-10: 설명 수준과 최근 문맥

두 함수는 문자열과 메시지를 만드는 일만 합니다. DB 조회나 AI 호출이 없어서
키 없이 테스트할 수 있고, 함수의 입력이 같으면 결과도 같습니다.

## 설명할 핵심 세 가지

1. **이번에 고른 수준을 사용합니다.** `prompts.py`의 `build_system_prompt(level)`은
   공통 안내에 easy / beginner / advanced 지침 하나를 붙입니다. 이전 턴의 수준을 기억하지
   않으므로 advanced에서 easy로 바꾸면 다음 호출의 지침도 easy로 바뀝니다.
2. **같은 사람·같은 대화의 완료 턴을 먼저 고릅니다.** `context.py`의 `build_messages()`는
   사용자 ID, 대화 ID, 완료 상태와 비어 있지 않은 질문·답변을 확인합니다. 그다음 생성 시각과
   ID로 정렬해 `max_turns`만큼 최근 턴을 `[user, assistant, ..., user(현재 질문)]`으로 만듭니다.
3. **오래된 질문·답변을 함께 뺍니다.** 과거 Q/A가 `max_chars`를 넘으면 가장 오래된 쌍부터
   제외합니다. 현재 질문과 시스템 지침은 유지합니다. 최신 한 쌍 자체가 예산보다 크면
   과거 문맥 없이 현재 질문만 전달합니다. 문자 수는 토큰 수와 다릅니다.

`HistoryTurn`은 DB 테이블이 아니라 문맥 함수의 입력 자료입니다. `frozen=True`는 자료의
필드를 실수로 바꾸지 못하게 합니다. 함수도 새 목록을 만들어 입력 목록을 변경하지 않습니다.

턴 수와 문자 예산은 기본값 없이 꼭 전달해야 하는 인자입니다. 기본값 5턴·12,000자는
`Settings.context_turns`, `Settings.context_max_chars`에만 두고, EE-13 서비스에서 읽어 전달합니다.
이렇게 하면 `.env`의 `CONTEXT_TURNS`, `CONTEXT_MAX_CHARS` 변경을 반영하면서 문맥 함수는
환경 변수를 직접 읽지 않는 순수 함수로 유지됩니다. 둘 중 하나가 0이면 과거 문맥 없이
현재 질문만 반환하고, 음수는 잘못된 설정을 알리는 `ValueError`로 거부합니다.

## 호출 예시

```python
from app.chat.context import build_messages
from app.chat.prompts import build_system_prompt

# EE-13에서 인증·소유권 확인·현재 질문 검증 후 사용합니다.
# settings는 SettingsDep로 받은 서버 설정입니다.
system = build_system_prompt("easy")
messages = build_messages(
    history=[],  # 새 대화에는 과거 문맥이 없습니다.
    user_id=user.id,  # 요청 본문의 ID가 아니라 서버 인증 결과입니다.
    conversation_id=conversation.id,
    question="API가 뭐야?",
    max_turns=settings.context_turns,
    max_chars=settings.context_max_chars,
)
# provider.generate_reply(messages, system=system, ...)에 각각 전달합니다.
```

첫 설명은 정의 → 설명/비유 → 예시 → 정리를 기본으로 안내합니다. 후속 질문인 “더 쉽게”,
“예시 하나 더”, “핵심만”에는 요청한 형식을 우선합니다. 새 대화라도 명확한 질문에는 바로
설명합니다. 같은 주제를 다시 묻거나 수준을 바꾸면 이번 수준으로 다시 설명하며, 질문이 짧거나
반복됐다는 이유만으로 모호하다고 판단하지 않습니다. 이전 답변의 난이도와 이전 턴의 요청보다
이번 수준을 우선합니다. 전공자 설명은 원리·전제·한계를 이번 답변 안에 포함합니다.
질문과 전달된 문맥을 확인한 뒤에도
설명 대상이 불분명할 때만 확인 질문 하나를 합니다. 실제로 없는 문맥을 아는 척하지 않는
보호는 유지합니다. 프롬프트는 지침이며 실제 AI 답변은 별도 샘플로 확인합니다.
[같은 질문의 수준 변경 검증](ISSUE-54.md)에는 프로그램의 입력 전달과 실제 답변을 구분해 기록합니다.

## EE-13 연결

- EE-05 PR #6과 동일한 `ChatMessage` 및 `system` 분리 계약을 사용합니다.
- A의 DB 조회·소유권 검사는 EE-11, 실제 AI와 `/api/chat` 연결은 [EE-13](EE-13.md)에서 담당합니다.
  `service.py`가 조회 결과를 `HistoryTurn`으로 옮겨 설정값과 함께 전달합니다. 이 함수의 필터는
  인증·DB 소유권 검사를 대신하지 않습니다.
- HTTP 질문 검증은 `schemas.py`, 실제 출력 토큰 한도는 `anthropic_provider.py`에서 적용합니다.
- 실제 AI 호출·생성 문장의 품질·실제 DB 권한 검증은 이번 순수 함수 테스트에 포함되지 않습니다.

검증: `uv run pytest tests/chat`, `uv run pytest`, `uv run ruff check .`.
