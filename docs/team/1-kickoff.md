## 1. 이 과제는 뭔가요?

### 한 줄 요약

**"ChatGPT 같은 AI 챗봇 웹사이트를 4명이 만들어서, 누구나 접속할 수 있게 인터넷에 올리기"** 입니다.

AI 를 직접 만드는 건 아니에요. 이미 있는 AI(Claude)에게 **우리 서버가 대신 질문을 전달하고 답을 받아오는** 서비스를 만듭니다.
그동안 따로 배운 리눅스, 웹, DB, AI API 를 **하나로 연결해 보는 것**이 목표예요.

### 우리 서비스: EasyExplain

> 모르는 개념을 물어보면 **"아주 쉽게 / 입문자 / 전공자"** 중 고른 수준으로 설명해 주고,
> "더 쉽게 설명해줘", "예시 하나 더" 처럼 이어서 물어보면 **앞 대화를 기억하고** 답해 주는 학습 챗봇

```
예시)
나: (아주 쉽게) API가 뭐야?
챗봇: API는 식당의 "주문서" 같은 거예요. 손님이 주방에 직접 들어가지 않고 ...
나: 그걸 다른 예시로 하나 더 들어줘
챗봇: 그럼 이번엔 리모컨으로 비유해 볼게요. 앞에서 말한 API처럼 ...   ← 앞 대화를 기억함
```

### 전체 구조 — 식당에 비유하면

| 부품 | 비유 | 하는 일 |
|---|---|---|
| 웹 화면 | 🍽️ 손님 테이블과 메뉴판 | 질문을 입력하고 답을 보는 곳 |
| 우리 서버 | 🧑‍💼 홀 직원 | 손님 확인(로그인), 주문을 요리사에게 전달, 주문 기록, 문제 생기면 안내 |
| AI (Claude) | 👨‍🍳 요리사 | 실제 설명을 만듦. 손님은 주방에 못 들어감 (🔑 AI 키는 서버만 가짐) |
| DB | 📒 주문 장부 | 누가 언제 뭘 물었고 어떤 답을 받았는지 기록 |

### 꼭 만들어야 하는 것 (과제 필수)

과제 문서에서 **"반드시"** 라고 한 것들이에요. 이것만 다 되면 합격선입니다.

- [ ] **웹 화면** — 질문을 입력하면 같은 화면에 답이 나온다
- [ ] **회원가입·로그인** — 로그인한 사람만 챗봇을 쓸 수 있다
- [ ] **AI 연결** — AI 는 서버에서만 부른다 (AI 키가 브라우저에 노출되면 안 됨)
- [ ] **대화 기억** — 이전 대화를 기억하고 이어서 답한다
- [ ] **대화 기록 저장** — 누가, 언제, 무엇을 물었고, 어떤 답을 받았는지 DB 에 쌓이고, 사람별로 볼 수 있다
- [ ] **서버 기록(로그)** — 질문이 들어옴 / AI 에게 물어봄 / AI 가 답함(또는 실패) / 저장 성공(또는 실패) 이 서버에 남는다
- [ ] **오류 처리** — AI 가 느리거나 실패해도 서버가 멈추지 않고 "잠시 후 다시 시도해 주세요" 같은 안내를 준다
- [ ] **입력 검사** — 빈 질문, 너무 긴 질문 등을 막는다
- [ ] **배포** — 평가하는 날, 우리 집 밖(외부 인터넷)에서도 접속되는 주소가 있다
- [ ] **협업 기록** — 작업은 브랜치 → PR → 리뷰 후 합치기, **각자 의미 있는 커밋 10개 이상**
- [ ] **문서** — README 에 구조, API, DB, 실행 방법, 각자 한 일 정리

우리 주제에 맞게 **추가로** 넣는 것: 설명 수준 3단계, [더 쉽게]·[예시 하나 더]·[핵심만] 버튼, 내 대화 목록

### 평가는 어떻게 받나요?

퍼실리테이터가 **코드를 같이 보면서 각자에게 맡은 부분을 질문**합니다.
그래서 "AI 가 짜 줬어요"가 아니라 **내가 만든 부분은 내가 설명할 수 있어야** 해요.
(준비 자료: [2-evaluation-example.md](2-evaluation-example.md))

### 지금 어디까지 되어 있나요?

팀장이 **뼈대**를 만들어 뒀어요. 집으로 치면 기둥과 방 구분, 전기 배선까지 해 둔 상태이고, 각 방의 가구(기능)는 아직 비어 있어요.

- ✅ 서버 켜기, 서버 상태 확인 주소(`/health`)
- ✅ 오류가 나면 모두 같은 모양으로 안내하는 장치
- ✅ 서버 기록(로그)을 남기는 장치
- ✅ 각 기능이 들어갈 자리 (지금은 "아직 안 만들었어요" 라고 대답함)
- ✅ 코드를 올리면 자동으로 검사해 주는 장치
- ⬜ 로그인, AI 연결, 화면, 기록 저장 → **이제 우리가 나눠서 만들 부분**

## 3. 커밋 메시지 쓰는 법

### 제안

```
종류(영역): 무엇을 했는지 한국어로

예) feat(auth): 회원가입 기능 추가
    fix(chat): AI 응답이 늦을 때 안내 문구가 안 나오던 문제 수정
    test(web): 로그인 화면 테스트 추가
```

| 종류 | 언제 |
|---|---|
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `test` | 테스트만 추가·수정 |
| `docs` | 문서만 수정 |
| `style` | 화면 꾸미기(CSS) |
| `refactor` | 동작은 같은데 코드 정리 |
| `chore` | 설정·패키지 같은 기타 |
| `ci` | 자동 검사 설정 |

**영역**은 폴더 이름을 그대로 써요: `auth`(로그인) `db` `conversations`(기록) `chat`(AI) `web`(화면) `core`(공통)

### 왜 이렇게 하나요?

- **커밋 목록만 봐도 누가 어느 부분을 했는지 보여요.** 과제에서 "각자 한 일"과 "실제 Git 기록"이 맞는지 확인하는데, 이게 그대로 증거가 됩니다.
- 많은 개발팀이 쓰는 방식이라 나중에 다른 프로젝트에서도 그대로 쓸 수 있어요.
- **한 커밋에는 한 가지 일만** 담으면 리뷰하기 쉽고, 각자 10개 이상이 자연스럽게 채워져요.
  (개수를 채우려고 의미 없는 커밋을 만들면 평가에서 오히려 티가 납니다)

## 4. 서버 주소(API) 정하기

**API 가 뭐냐면:** 화면이 서버에게 "이거 해 줘"라고 요청하는 **주소와 약속**이에요.
화면 담당(C)과 서버 담당(A·B)이 이 약속만 맞추면, 서로 기다리지 않고 따로 만들어도 나중에 딱 맞물립니다.

### 제안하는 주소

| 주소 | 하는 일 | 담당 |
|---|---|---|
| `POST /api/auth/signup` | 회원가입 | A |
| `POST /api/auth/login` | 로그인 | A |
| `POST /api/auth/logout` | 로그아웃 | A |
| `GET /api/auth/me` | 지금 로그인한 사람이 누군지 | A |
| `POST /api/conversations` | 새 대화 시작 | A |
| `GET /api/me/conversations` | 내 대화 목록 | A |
| `GET /api/conversations/{대화번호}` | 대화 하나 자세히 보기 | A |
| `GET /api/me/chats` | 내 질문·답변 기록 전체 | A |
| `POST /api/chat` | 질문 보내고 답 받기 | B |
| `/` `/signup` `/login` `/chat` `/history` | 화면 페이지들 | C |

질문을 보낼 때는 이렇게 보내고, (이해를 돕기 위해 줄인 예시예요. 실제 필드는 [spec/api.md](../spec/api.md) 3·4장을 따라요)

```json
{ "conversation_id": "대화번호", "question": "API가 뭐야?", "level": "easy" }
```

문제가 생기면 **어떤 기능이든 항상 같은 모양**으로 알려 줍니다.

```json
{ "error": { "code": "AI_TIMEOUT", "message": "응답이 지연되고 있어요. 잠시 후 다시 시도해 주세요." } }
```

전체 내용은 [spec/api.md](../spec/api.md) 에 있어요.

### 왜 이렇게 정했나요?

- **화면과 서버를 한 곳에서 운영해요.** 따로 나누면 배포할 곳이 2개가 되고 설정도 복잡해져요.
- **`/api/me/chats` 는 과제 문서의 예시와 똑같은 주소예요.** 평가자가 바로 알아봅니다.
- **"누가 물어봤는지"는 화면이 알려 주지 않고 서버가 로그인 정보로 판단해요.**
  화면이 "나는 3번 사용자야"라고 보내게 하면, 누군가 숫자만 바꿔서 남인 척할 수 있거든요.
- **"대화" 단위로 묶어요.** 새 대화를 시작하면 이전 대화 내용이 섞이지 않고, 기록 화면에서도 대화별로 보기 좋아요.
- **남의 대화를 열려고 하면 "없는 대화"라고 답해요.** "권한 없음"이라고 하면 그 대화가 있다는 걸 알려 주는 셈이라서요.
- **오류 모양을 하나로 통일해요.** 화면 담당은 `message` 만 보여 주면 되니까 오류마다 따로 처리할 필요가 없어요.
- **질문은 1~2,000자.** 빈 질문을 막는 건 과제 필수이고, 너무 긴 질문은 AI 비용과 대기 시간을 늘려서요.
- **로그인 유지는 서버가 기억하는 방식이에요.** 로그아웃하면 서버에서 바로 지워져서 그 즉시 못 쓰게 됩니다.

### 처음엔 단순하게, 시간 남으면 추가하기

원래 계획에는 안전장치가 많은데, **과제 필수가 아닌 건 나중으로 미루는 걸** 제안해요. 처음부터 다 하려다 필수 기능을 놓치면 안 되니까요.

| 기능 | 과제 필수? | 제안 |
|---|---|---|
| 로그인한 사람만 사용, 남의 대화 못 봄 | ✅ | 먼저 |
| 오류 안내, 입력 검사, AI 대기 시간 제한 | ✅ | 먼저 |
| 다른 사이트가 몰래 요청 보내는 공격 막기 (CSRF) | ❌ | ~~기본 방어만~~ → **먼저** (로그인 후 상태 변경 요청에 `X-CSRF-Token` 확인, EE-08) |
| 전송 버튼 두 번 눌렀을 때 중복 처리 | ❌ | ~~화면 버튼 잠그기만~~ → **먼저**: 화면 버튼 잠그기 + 서버의 `client_request_id` 중복 확인 (EE-16) |

> **회의 후 결정:** 두 기능 모두 API·DB 명세 v1 과 뼈대 코드에 이미 자리가 잡혀 있어서 **처음부터 포함**하기로 했어요.
> 나중에 넣으면 DB 칸과 API 응답을 다시 바꿔야 하기 때문이에요.
| 질문 횟수 제한 | ❌ | **먼저, 대신 간단하게** (아래 설명) |

#### 질문 횟수 제한은 왜 먼저 하나요?

필수는 아니지만, **필수 기능인 "AI 답변"을 지키려면** 필요해요.

- 평가 때 서비스 주소가 공개되니까 **누구나 가입해서 질문**할 수 있어요.
- AI 키는 코디세이에서 받은 **키 하나를 같이 쓰고**, 사용량에 한도가 있을 수 있어요.
- 누가 장난으로 질문을 수백 번 보내면, **평가 당일에 키 한도가 다 떨어져서 AI 가 대답을 못 할 수도** 있어요.

그래서 처음부터 **두 가지만** 간단하게 막아요.

| 제한 | 제안 값 | 막는 것 |
|---|---|---|
| 한 사람이 1분에 보낼 수 있는 질문 | **10번** | 한 계정이 연달아 마구 보내는 것 |
| 서비스 전체가 하루에 AI 에게 보내는 질문 | **200번** | 계정을 여러 개 만들어서 보내는 것까지 포함한 총량 |

- 넘으면 AI 를 부르지 않고 "잠시 후 다시 시도해 주세요" 안내를 보여 줘요. (오류 코드 `RATE_LIMITED`)
- 숫자는 설정 파일에서 바꿀 수 있어요. 평가 인원과 키 한도를 보고 조정하면 돼요.
- 서버를 1대만 쓰니까 **서버 메모리에 횟수만 세는 정도**로 충분해요. (담당: B, 채팅 기능 안에서)
- 남은 일: 코디세이 AI 키의 실제 사용량 한도를 확인해서 숫자를 정하기 (팀장)

## 5. 데이터 저장 방식(DB) 정하기

### 제안: 표 4개

```
회원(users) ─┬─ 로그인 기록(auth_sessions)
             ├─ 대화(conversations) ─┐
             └─ 질문과 답(chat_turns) ◀┘
```

| 표 | 무엇을 저장하나 | 예시 |
|---|---|---|
| **회원** | 이메일, 비밀번호(암호화된 형태), 가입 시각 | kim@test.com |
| **로그인 기록** | 누가 언제 로그인했고 언제 만료되는지 | 2시간 뒤 만료 |
| **대화** | 누구의 대화인지, 제목, 만든 시각 | "API가 뭐야?" 대화 |
| **질문과 답** | 질문 1개 + 답 1개를 한 줄로, 설명 수준, 처리 상태, 시각 | (아주 쉽게) API가 뭐야? → API는 식당의 주문서… |

자세한 칸 이름은 [spec/db.md](../spec/db.md) 에 있어요.

### 왜 이렇게 정했나요?

- **SQLite 를 써요.** 과제가 추천하는 DB 이고, 따로 설치할 필요 없이 파일 하나로 동작해서 기능 만드는 데 집중할 수 있어요.
- **비밀번호는 원래 글자로 저장하지 않아요.** 되돌릴 수 없는 형태로 바꿔서 저장해서, DB 가 유출돼도 비밀번호를 알 수 없어요.
- **질문과 답을 한 줄에 같이 저장해요.** 과제가 요구한 "누가, 언제, 무엇을 묻고, 어떤 답을" 이 한 줄에 다 있어서 확인하기 쉽고,
  "최근 대화 5개 기억하기"도 "최근 5줄 가져오기"로 간단해져요.
- **처리 상태(처리 중 / 완료 / 실패)를 같이 저장해요.** 질문을 먼저 저장한 다음 AI 에게 물어보기 때문에,
  AI 가 실패해도 "이 질문은 실패했다"는 기록과 이유가 남아요. 실패한 대화는 AI 에게 기억시키지 않을 수도 있고요.
- **대화 번호는 1, 2, 3 이 아니라 긴 무작위 문자열이에요.** 숫자면 남의 대화 번호를 쉽게 짐작할 수 있어서요.
- **시각은 세계 표준시로 저장하고, 화면에서 한국 시간으로 보여 줘요.** 서버가 어느 나라에 있든 시간이 꼬이지 않아요.
- **로그인 기록을 DB 에 둬요.** 로그아웃하거나 시간이 지나면 서버에서 바로 지워서 다시 못 쓰게 할 수 있어요.

### 🙋 같이 정해요
- [x] (A·B) "질문과 답을 한 줄에" 방식, 괜찮나요?
- [x] 비밀번호는 ~~10자 이상으로 할까요? (10~128자)~~ → **8~64자, 영어만** (EE-09 PR #38 에서 변경, [spec/api.md](../spec/api.md) 2장)
