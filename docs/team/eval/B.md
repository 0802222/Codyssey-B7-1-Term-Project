# 🤖 B 나현준 평가 대비 — AI 호출, 설명 수준, 문맥 유지, AI 오류

[공통 문서](../2-evaluation-example.md)의 답변 요령(2장)과 진행 대본(3장)을 먼저 읽고, 이 파일로 **내 영역**을 준비합니다.
이 파일은 담당자가 직접 고칩니다. 하지 않은 일을 한 것처럼 쓰지 않습니다.

## 1. 예상 질문과 답

**🧑‍🏫 퍼실:** B 님, 질문 하나가 들어오면 서버에서 어떤 순서로 처리되나요?

**🤖 B:** `app/chat/` 의 〔파일명〕 기준으로 설명드리겠습니다.

```
① 입력 검증 (빈 질문, 2,000자, level 값)
② 질문을 "처리 중(pending)" 상태로 먼저 저장
③ 같은 대화의 최근 5턴을 DB 에서 조회
④ 시스템 지침 + 이전 대화 + 현재 질문으로 AI 호출 (최대 30초)
⑤ 성공하면 답변을 저장하고 "완료(completed)"로 변경 → 화면에 반환
   실패하면 "실패(failed)"와 오류 코드를 저장 → 오류 안내 반환
```

**🧑‍🏫 퍼실:** AI 호출을 브라우저에서 바로 하면 더 간단하지 않나요?

**🤖 B:** 그러면 브라우저에 API 키가 들어가야 해서 누구나 키를 볼 수 있게 됩니다.
그래서 **AI 호출은 서버에서만** 하고, 키는 서버의 `.env` 에만 있습니다. 브라우저는 결과 텍스트만 받습니다.

**🧑‍🏫 퍼실:** 문맥 유지는 어떻게 구현했나요?

**🤖 B:** 같은 대화에서 **완료된 최근 5턴**을 오래된 순서로 `질문, 답변, 질문, 답변…` 배열로 만들고, 마지막에 현재 질문을 붙여서 AI 에 보냅니다.
실패한 턴은 넣지 않습니다. 그래서 "그걸 음식점에 비유해줘"라고 하면 앞에서 물어본 API 를 알고 답할 수 있습니다.

**🧑‍🏫 퍼실:** 왜 5턴인가요? 대화가 아주 길어지면요?

**🤖 B:** 많이 보낼수록 응답이 느려지고 비용이 늘어서, 후속 질문에 충분한 정도로 5턴을 골랐습니다.
그래도 너무 길면 과거 대화가 12,000자를 넘을 때 가장 오래된 것부터 뺍니다. 두 값 모두 설정으로 바꿀 수 있습니다.

**🧑‍🏫 퍼실:** 새 대화를 시작하면 이전 대화 내용이 섞이지 않나요?

**🤖 B:** 문맥은 **같은 대화 ID** 안에서만 가져오기 때문에 섞이지 않습니다. 이 부분은 테스트로 확인했습니다. → `tests/chat/〔테스트명〕`

**🧑‍🏫 퍼실:** AI 가 응답을 안 주면 어떻게 되나요?

**🤖 B:** 30초 타임아웃을 걸어 두었습니다. 시간이 넘으면 `504 AI_TIMEOUT` 과 "응답이 지연되고 있어요" 안내를 돌려주고,
그 질문은 실패 상태로 저장합니다. **서버는 죽지 않고 다음 요청을 계속 받습니다.**
자동 재시도는 하지 않습니다. 재시도하면 사용자가 더 오래 기다리고 비용도 늘어서, 다시 시도는 사용자가 직접 하게 했습니다.

**🧑‍🏫 퍼실:** 그 상황을 실제로 어떻게 확인했나요?

**🤖 B:** 실제 AI 를 일부러 느리게 만들 수는 없어서, **가짜 AI 가 타임아웃을 내도록** 한 테스트로 확인했습니다.
서버 로그에는 같은 요청 ID 로 `ai_call_start` 다음에 `ai_call_failed` 가 남습니다.

> 💡 "왜 이렇게 했나"에는 **다른 선택지와 비교**해서 답하면 좋습니다. (브라우저 호출 vs 서버 호출, 재시도 vs 미재시도)
