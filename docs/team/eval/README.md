## 채울 것

1. **예상 질문과 답** — `〔 〕` 칸을 실제 파일명·테스트명·PR 번호로. 지금 코드와 다른 답은 고칩니다. 하지 않은 일은 쓰지 않습니다.
2. **읽을 코드 표** — 평가 때 열어서 가리킬 파일 3~6개와 "무엇을 보여 주나" 한 줄, 관련 테스트
3. **결과 예측 → 실제 실행** — 명령·화면 동작 2~3개. 예측을 먼저 쓰고 실제로 돌려 본 결과를 씁니다
4. **준비 메모** — 리허설에서 막힌 질문

[L.md](L.md) 가 채운 예시입니다.

## 순서 (처음 한 번)

```bash
git fetch origin
git switch docs/ee-24-eval-answers          # 팀장이 만든 브랜치로 이동
```

## 순서 (고칠 때마다)

```bash
git pull                                     # ① 다른 사람 커밋 먼저 받기 (파일이 달라 충돌 없음)
# ② 내 파일만 고침: docs/team/eval/<내 역할>.md
git add docs/team/eval/<내 역할>.md
git commit -m "docs: <역할> 평가 답변 메모 채움"
git push                                     # ③ 거절되면 git pull 후 다시 push
```

- 다른 사람 파일과 `README.md` 등은 고치지 않습니다.
- **다 채웠으면 단톡에 알려 주세요.** 모두 끝나면 팀원 한 명이 PR 을 승인하고 팀장이 머지합니다.
  새 커밋이 올라오면 승인이 취소되므로, 승인은 **모두 push 를 끝낸 뒤**에 합니다.
